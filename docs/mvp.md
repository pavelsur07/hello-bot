# Границы текущего MVP

Один бот получает личные текстовые сообщения Telegram через long polling,
ищет опубликованный Markdown-раздел и отправляет его текст с источником.
Если ответа нет, предлагает уточнить вопрос или обратиться к оператору.
Автоматическая передача оператору пока не интегрирована.

## Включено

- Нормализация Telegram-событий в InboundMessage; остальные события игнорируются.
- Поиск по словам, опубликованные статьи и стабильные ссылки на разделы.
- Один процесс; SQLite хранит только (channel, external_event_id, status).
- Защита от повторов, обработка ошибок API, безопасный ответ при длинном разделе.
- Неизвестный исход отправки останавливает процесс; pending блокирует рестарт.
- Демо без ключей, проверки импортов, формата, линтера, типов, тестов и сборки.

## Исключено

Веб-чат, MAX, вебхуки, worker, PostgreSQL, векторная БД, генерация моделей,
классификация Jev, автоматическая передача человеку, заказы/платежи, история
диалога и идентификация между каналами. Наличие модулей и контрактов для будущих
задач не означает, что они реализованы.

Также исключены многопроцессный polling, автоматический сброс pending,
гарантия exactly-once во внешнем API и публикация пакета в реестр.

## Проверяемые критерии

| Критерий | Подтверждение |
| --- | --- |
| Воспроизводимая установка на Python 3.12+ | Команды README, requirements-dev.txt |
| Известный вопрос даёт ответ и источник | test_telegram_flow.py, демо |
| Пустые знания, черновики и случайное общее слово не дают выдуманный ответ | test_markdown_knowledge.py, test_telegram_flow.py |
| Повтор отправленного события не создаёт второй ответ | test_sqlite_events.py, test_telegram_flow.py |
| Ошибки сети/HTTP/JSON контролируются, токен не появляется в ошибке | test_telegram_adapter.py |
| Неизвестная доставка не вызывает слепой повтор; pending блокирует рестарт | test_telegram_flow.py, test_telegram_polling.py |
| Сценарии и контракты не импортируют инфраструктуру | test_architecture.py |
| Локальные проверки совпадают с CI | python scripts/check.py в checks.yml |
| Установка wheel работает без исходного PYTHONPATH | Финальное демо scripts/check.py в отдельной среде |

Локальные проверки работают без живых ключей и клиентских API.
Первоначальная установка инструментов требует PyPI. CI настроен на Python
3.12 и 3.14; локальный прогон подтверждает только установленную версию.

## Проверки следующих этапов

Настоящий Telegram API требует ручной проверки с токеном тестового бота.
Для Jev подготовлены синтетические обращения в
tests/fixtures/classification_cases.json, включая неопределённые запросы.
Сейчас тестируется диапазон и сохранение низкой confidence в IntentDecision.
Выбор уточнения/человека и качество классификатора будут проверены после его
реализации. Низкая уверенность не является подтверждённой категорией;
other не является синонимом низкой уверенности.
