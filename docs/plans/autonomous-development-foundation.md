# Подготовка проекта к автономной разработке

Цель: сохранить работающий Telegram → Markdown сценарий и сделать его границы,
запуск и проверки однозначными для следующего агента. Основание — задача пользователя
от 2026-10-07; новые бизнес-функции и смена архитектуры исключены.

## Ограничения и решения

- Python 3.12+, модульный монолит, unittest, SQLite и Markdown остаются.
- Пользователь согласовал Ruff, mypy и build только для разработки.
- SDK моделей, вебхуки, другие каналы и автоматическая маршрутизация не добавляются.
- Классификация существует только в виде контрактов: проверим валидность её
  результата и сохраним неопределённые обращения для будущей оценки; качество
  Jev и действие при низкой уверенности пока нельзя проверить сквозным тестом.
- Один polling-процесс. Успешная отправка и SQLite не образуют общей транзакции;
  неизвестный исход отправки требует остановки, а не слепого повтора.

## Критерий готовности

Документированные команды работают в виртуальной среде; локальная команда и CI
вызывают один сценарий проверок; существующие сценарии проходят без сети и ключей;
формат, линтер, типы и сборка подтверждены фактическим выводом; независимое ревью
выполнено. Реальный Telegram API и будущая маршрутизация обозначены как непроверенные.
